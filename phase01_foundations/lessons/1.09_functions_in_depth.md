# 1.09 — Functions in depth

This module covers the function features that make agent-written code hard to read until you know them: defaults, keyword arguments, `*args`, `**kwargs`, and functions passed around as values.

## Default values and keyword arguments

```python
def apply_discount(price, pct=10, round_to=2):
    return round(price * (1 - pct / 100), round_to)

apply_discount(200)                  # 180.0   pct and round_to use defaults
apply_discount(200, 25)              # 150.0   positional
apply_discount(200, round_to=0)      # 180.0   keyword: skip pct, set round_to
apply_discount(price=200, pct=5)     # keywords can be in any order
```

Keyword arguments make calls self-documenting: `connect(timeout=30, retries=3)` beats `connect(30, 3)`.

## Keyword-only arguments (after `*`)

```python
def export(data, *, fmt="csv", overwrite=False):
    ...

export(rows, fmt="json")      # fine
export(rows, "json")          # TypeError - must be named
```

Library code uses this a lot to force readable calls.

## `*args` — any number of positional arguments

```python
def total(*amounts):          # amounts is a tuple
    return sum(amounts)

total(1, 2, 3)                # 6
nums = [4, 5]
total(*nums)                  # 9 - `*` at the CALL unpacks a list into arguments
```

## `**kwargs` — any number of keyword arguments

```python
def build_query(**filters):   # filters is a dict
    return "&".join(f"{k}={v}" for k, v in filters.items())

build_query(region="west", year=2026)     # 'region=west&year=2026'
opts = {"region": "east"}
build_query(**opts)                        # `**` at the call unpacks a dict
```

You'll see `def __init__(self, *args, **kwargs):` and `super().__init__(*args, **kwargs)` everywhere in framework code: it means *"accept anything, and pass it all along"*.

Full order: `def f(a, b=2, *args, c, d=4, **kwargs)`.

## The mutable default trap

```python
def add_item(item, basket=[]):       # BUG: the [] is created ONCE, when def runs
    basket.append(item)
    return basket

add_item("a")    # ['a']
add_item("b")    # ['a', 'b']  <- surprise: same list as last time

def add_item(item, basket=None):     # FIX
    if basket is None:
        basket = []
    basket.append(item)
    return basket
```

Never use a list, dict or set as a default value. Use `None` and create it inside.

## Scope

```python
RATE = 0.18                 # global - readable inside functions

def with_vat(x):
    return x * (1 + RATE)   # reads the global: fine

counter = 0
def bump():
    counter += 1            # UnboundLocalError: assigning makes it local
```

Rule: functions should get what they need from **parameters** and give results back with **return**. Reading constants from outside is OK; changing outside variables is a smell (the `global` keyword exists, but avoid it).

## Functions are values

A function is an object like any other: you can store it, pass it and return it.

```python
def double(x):
    return x * 2

f = double          # no parentheses: the function itself, not a call
f(5)                # 10

def apply_to_all(func, items):
    return [func(x) for x in items]

apply_to_all(double, [1, 2, 3])     # [2, 4, 6]
apply_to_all(str.upper, ["a"])      # ['A']
```

## `lambda` — a tiny unnamed function

```python
lambda x: x * 2              # same as double, written inline
lambda a, b: a + b
```

Mostly used as the `key=` for sorting, `min` and `max`:

```python
txs = [{"m": "A", "amt": 50}, {"m": "B", "amt": 20}]
sorted(txs, key=lambda t: t["amt"])                    # by amount
max(txs, key=lambda t: t["amt"])                       # biggest transaction
sorted(people, key=lambda p: (p["age"], p["name"]))    # by age, then name
sorted(people, key=lambda p: (-p["score"], p["name"])) # score high→low, then name A→Z
```

`key=` means: *"for each item, compute this value, and sort by it"*.

If a lambda gets complicated, write a normal `def` instead.

## Returning functions (closures preview)

```python
def make_multiplier(n):
    def multiply(x):
        return x * n        # remembers n from when it was created
    return multiply

triple = make_multiplier(3)
triple(10)     # 30
```

This is the foundation of decorators (Phase 4).
