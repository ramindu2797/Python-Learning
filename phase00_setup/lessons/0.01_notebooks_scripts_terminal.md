# 0.01 — Notebooks, scripts and the terminal

You'll use two ways of running Python in this course. Knowing when to use which saves hours of confusion later.

## Notebooks (`.ipynb`)

A notebook is a list of **cells**. A code cell runs in a background Python process called the **kernel**, which *remembers everything you've run* until you restart it.

| Action | Shortcut (VS Code) |
|---|---|
| Run cell | `Ctrl+Enter` |
| Run cell and move to next | `Shift+Enter` |
| Add cell below | `B` (in command mode — press `Esc` first) |
| Delete cell | `D D` (command mode) |
| Switch cell to Markdown / Code | `M` / `Y` (command mode) |
| Restart kernel | toolbar → *Restart* |

The big trap: **the kernel remembers state in the order you ran cells, not the order they appear.**

```python
# Cell A
x = 10
```
```python
# Cell B
print(x * 2)
```

Run A then B → `20`. Now edit A to `x = 5` but *don't run it*, run B → still `20`. The screen and the kernel now disagree. That's why every notebook in this course must pass **Restart → Run All** before you call it done.

The last expression in a cell is displayed automatically; anything earlier needs `print()`:

```python
a = 3
a + 1        # not shown - not the last line
a * 10       # shown: 30
```

## Scripts (`.py`)

A script is a plain text file run from top to bottom in a *fresh* Python process every time. No hidden state. Run it from the VS Code terminal (`` Ctrl+` ``):

```bash
python hello.py
```

Try it: create `phase00_setup/hello.py` containing

```python
name = "Ramindu"
print(f"Hello, {name}!")
print("2 + 3 =", 2 + 3)
```

and run it from the terminal. Use the terminal, not the ▷ button — you need to be comfortable with the command line for later phases.

Useful terminal basics:

| Command | Meaning |
|---|---|
| `pwd` (macOS/Linux) / `cd` alone (Windows) | where am I? |
| `ls` / `dir` | list files |
| `cd folder` / `cd ..` | move into a folder / up one level |
| `python file.py` | run a script |
| `python` | interactive Python (exit with `exit()`) |

## When to use which

| Use a notebook for… | Use a script for… |
|---|---|
| Practice problems, exploring data, trying ideas | Code that other code imports (modules) |
| Seeing tables and charts inline | Command-line tools, scheduled jobs |
| Lessons in this course (Phases 0–2 mostly) | Tests (pytest), packages, anything production |

The agent code you review at work is almost all `.py` modules, so from Phase 3 onward you'll write both.

## Common mistakes

- **Running the wrong kernel.** Check the kernel name in the top-right of the notebook says `pyfluent`.
- **Forgetting that `print` and "display" differ.** Inside a function or loop only `print` shows anything.
- **Editing a cell and not re-running it.** When in doubt, Restart → Run All.
