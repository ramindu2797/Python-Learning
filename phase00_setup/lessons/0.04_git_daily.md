# 0.04 — Git as a daily habit

You're new to git and your team uses it, so this course doubles as git practice: commit at the end of every session. You'll learn branches and pull requests properly in Phase 5; for now, five commands.

## The mental model

Git takes **snapshots** of your folder. You choose what goes into the next snapshot (*staging*), then save it with a message (*commit*).

```text
working folder  --git add-->  staging area  --git commit-->  history
```

## The five commands

```bash
git status                       # what changed? what's staged?
git add .                        # stage everything that changed (or: git add path/to/file)
git commit -m "1.05 loops: problems 1-4"
git log --oneline                # list of snapshots, newest first
git diff                         # what changed since the last commit (before staging)
```

VS Code's **Source Control** panel (`Ctrl+Shift+G`) does the same with buttons — use whichever you like, but know the commands, because that's what you'll see in documentation and at work.

## Good commit messages

Short, present tense, specific: `2.03 two pointers: valid palindrome + merge sorted`. Not `update` or `stuff`.

## What not to commit

The included `.gitignore` already excludes the usual junk (`__pycache__`, `.ipynb_checkpoints`) and secrets (`.env`). **Never commit API keys** — once pushed, assume they're leaked.

## Notebooks and git

Notebooks store their outputs inside the file, so diffs can be noisy. Fine for practice. For work repos, clear outputs before committing (*Clear All Outputs* in the toolbar) unless the team says otherwise.

## Daily routine

```bash
git add .
git commit -m "<module>: <what you did>"
```

Two lines, every session. After a few weeks, `git log --oneline` becomes a record of your progress.
